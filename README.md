# nist-800-53-control-mapping

[![tests](https://github.com/CauseSpark/nist-800-53-control-mapping/actions/workflows/tests.yml/badge.svg)](https://github.com/CauseSpark/nist-800-53-control-mapping/actions/workflows/tests.yml)

Map NIST SP 800-53 Rev. 5 baselines, the SP 800-171 Rev. 3 crosswalk, and example Splunk detections to each other, then report which controls the detections actually support.

## Purpose

I built this while moving from SOC work (Splunk, Security Onion) into governance, risk, and compliance. It connects the two worlds. A detection engineer thinks "this search catches brute force." An assessor thinks "what evidence supports AC-7?" This repo answers both questions from the same data.

It is personal study material. All environment details refer to **Harborlight Logistics**, a fictional company.

## Versions used

| Source | Version | Where the data came from |
|---|---|---|
| [NIST SP 800-53 Rev. 5](https://csrc.nist.gov/pubs/sp/800/53/r5/upd1/final) | Release 5.2.0 (Aug 27, 2025) | OSCAL catalog |
| [NIST SP 800-53B](https://csrc.nist.gov/pubs/sp/800/53/b/upd1/final) | Release 5.2.0 (baselines unchanged from 5.1.x) | OSCAL Low, Moderate, High, and Privacy baseline profiles |
| [NIST SP 800-171 Rev. 3](https://csrc.nist.gov/pubs/sp/800/171/r3/final) | May 2024 | OSCAL catalog, which lists the 800-53 source controls for each requirement |

The CSVs in `data/` were generated by `scripts/build_data.py` from NIST's official [usnistgov/oscal-content](https://github.com/usnistgov/oscal-content) repository at commit `f0de6d8` (Oct 22, 2026). Only control IDs, short titles, and baseline membership are included. For control text, use the official publications or the [Cybersecurity and Privacy Reference Tool (CPRT)](https://csrc.nist.gov/projects/cprt/catalog).

The 800-171r3 to 800-53 crosswalk here is the source-control list NIST publishes with each 800-171r3 requirement. NIST also publishes a [CUI Overlay](https://csrc.nist.gov/pubs/sp/800/171/r3/final) spreadsheet with item-level tailoring detail.

## Quick start

```bash
git clone https://github.com/CauseSpark/nist-800-53-control-mapping.git
cd nist-800-53-control-mapping
python -m pip install -r requirements-dev.txt
python -m pytest

# Moderate baseline, counts per family
python -m src.baseline_selector --baseline moderate --summary

# What High adds on top of Moderate, Audit family only
python -m src.baseline_selector --baseline high --diff-from moderate --family AU

# 800-53 controls behind two 800-171r3 requirements
python -m src.baseline_selector --from-171 03.01.01 03.03.05

# Which Moderate controls the detections support
python -m src.coverage_report --baseline moderate
```

A sample report is in [docs/sample_coverage_moderate.md](docs/sample_coverage_moderate.md). Full walkthrough: [docs/how_to_use.md](docs/how_to_use.md).

## Repository layout

```
data/
  baselines_rev5.csv          1,014 active controls and enhancements with Low/Moderate/High/Privacy flags
  crosswalk_171_to_53.csv     97 active 800-171r3 requirements -> 800-53r5 source controls
  detections_to_controls.csv  detection -> control it supports, with a one-line rationale
detections/splunk/*.spl       seven original example searches
scripts/build_data.py         rebuilds the two NIST CSVs from OSCAL
src/baseline_selector.py      filter by baseline, family, baseline diff, or 800-171r3 requirement
src/coverage_report.py        Markdown coverage report for a baseline
tests/                        pytest suite, run in GitHub Actions on every push
docs/how_to_use.md            walkthrough and how to add a detection
```

## What this demonstrates

- **Control framework fluency.** Working knowledge of how 800-53, 800-53B baselines, and 800-171 relate, and the tailoring between them.
- **Honest control mapping.** Detections "support" controls; they don't "satisfy" them. Coverage counts exact control IDs, so an enhancement (AC-2(4)) doesn't quietly credit its base control (AC-2). The report says plainly that a SIEM can only evidence a small share of a baseline.
- **Detection engineering.** Splunk searches for common Windows security events, each with data source, tuning, and false-positive notes.
- **Data you can trust.** Data comes from NIST's machine-readable OSCAL, not hand typing. Tests check it against NIST's published counts (Low 149, Moderate 287, High 370, Privacy 96) and check that the CSV mapping matches each search's header.
- **Engineering hygiene.** Small, readable Python with no runtime dependencies, unit tests, and CI.
